# Source provenance

This is the provenance register for raw evidence. Project status belongs in [STATUS](../STATUS.ko.md), and remaining work in [BACKLOG](../BACKLOG.ko.md). Preserve existing snapshots; add a new filename, collection context and interpretation when collecting new evidence. Do not store signing secrets.

`L1Read.sol` retrieved on 2026-09-18; JSON observations carry their own collection dates.

`L1Read.sol` is an unmodified MIT-licensed attachment from the official [Interacting with HyperCore](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/hyperevm/interacting-with-hypercore) page.

Attachment URL: [official L1Read.sol](https://2356094849-files.gitbook.io/~/files/v0/b/gitbook-x-prod.appspot.com/o/spaces%2FyUdp569E6w18GdfqlGvJ%2Fuploads%2FLXZLGWjNoZCV4IpfEQUJ%2FL1Read.sol?alt=media&token=f19b1226-95bc-4ad4-9bbc-a55665676b92).

The probe JSON files were generated by `scripts/probe.py` from public Hyperliquid RPC/info endpoints. Each file records its own timestamp, network and pinned EVM block. HTTP info calls are not block-pinned. Raw price and quantity fields retain their source encoding; do not normalize them without verifying the appropriate units.

`mainnet-corewriter-observation-2026-09-19.json` records a read-only cross-check of public CoreWriter logs against fills returned by the official mainnet Info API. It proves that action 1 from a contract was executed for the cited transactions. Its 100,000-block scan did not find action 15 or 16, which is recorded only as “not observed,” not as proof that those actions are unavailable.

These snapshots establish read support at the recorded blocks. They do not establish successful writes, strategy profitability, contract-account eligibility, or withdrawal liveness.

The `nav-*.json` files from September 20–21, 2026 record read-only accounting probes and public PM account discovery. `nav_probe.py` pins all precompile reads to one EVM block number and checks the header hash again after collection; API observations remain unpinned. `nav-pm-hype-carry-2026-09-21.json` includes pinned token/perp metadata, a nonzero HYPE short and nonzero USDC debt. `nav_reconcile.py` produces the corresponding diagnostic reconciliation; it does not certify complete NAV or authorize deposits. Failed lending reads in the other samples are retained as failures, never zero debt. See [findings and limitations](../pm-nav-evidence.ko.md).


`managed-mainnet-preflight-2026-10-04.json` was collected by `scripts/managed_mainnet.py` from the public mainnet EVM RPC at the block/hash recorded inside it. It includes raw USDC/Circle/CoreWriter code, USDC decimals and Core block read, plus a final EVM block-hash check. No user account was queried and no signed action or funds were sent. This is bytecode-presence/read compatibility evidence, not implementation-source verification, a Core deposit/recall experiment or a production verifier proof. The first sandboxed attempt failed to reach the network; the successful read-only network run is the new file preserved here.

`managed-precompile-modes-2026-10-04.json` and its separate reconciliation record block-pinned reads of three previously documented public accounts. Standard/Unified lending failures are retained. `managed-outcome-meta-2026-10-04.json` is an unpinned HTTP discovery response. `managed-outcome-precompile-2026-10-04.json` and `managed-outcome-after-expiry-2026-10-04.json` use `scripts/outcome_probe.py` to record encoded-ID capabilities and the same outcome's active→settled transition. Metadata and post-settlement balance/price failures remain failures; zero observed balances do not prove quantity precision or payout. No signed actions or funds were sent. [Interpretation and implementation fixes](../managed-precompile-evidence.ko.md).

`managed-equity-modes-2026-10-04.json` and `managed-equity-modes-rerun-2026-10-04.json` were collected by `scripts/equity_probe.py` from public mainnet accounts in every abstraction mode. Each account has its own pinned EVM block and a final block-hash check; HTTP reads before and after are unpinned. The first run's classifier had no one-raw-unit tolerance and reports two Portfolio Margin USDC totals that differ from the API by exactly 1e-8 as `Mismatch`; the file is preserved unchanged. The rerun adds HyperCore vault equity reads and that tolerance; its single vault `Mismatch` is HLP equity moving non-monotonically between the two HTTP reads. Both support the per-venue identity used by the Managed NAV source. They do not prove whole-account completeness, cover non-USDC collateral DEXes, or observe a mode switch. No signed actions or funds were sent. [Interpretation](../managed-precompile-evidence.ko.md#raw-ledger-identity).

`managed-precompile-gas-2026-10-04.json` and `managed-precompile-gas-control-2026-10-04.json` were collected by `scripts/precompile_gas_probe.py`. Each is one `eth_call` session pinned to the recorded block with a final block-hash check: the creation code of `test/mainnet/PrecompileGasProbe.sol` runs gas-capped static calls to read precompiles and returns the results, so nothing was signed, sent or deployed. They record the smallest cap at which each read answered, the gas an erroring read consumed, and (second file) that the validator-DEX margin summary answers for an address unknown to Core. Every boundary equalled `1000 + 33 * (input_len + output_len)`, about half the documented cost. This is a measurement of individual precompile calls at one time, not of a Vault transaction, and the cost is not a protocol constant.

`managed-vault-equity-edge-2026-10-04.json` records one pinned block of `userVaultEquity` reads for a public account against two closed HyperCore vaults, one open vault, the account's own address and the zero address. Closed and open vaults returned zero equity; a non-vault address was a precompile error. Vault open/closed status came from an unpinned HTTP listing. It is a small edge-case sample, not a statement about every vault state.

`managed-scope-watch-2026-10-04.json` is one read-only run of `scripts/scope_watch.py` against a public mainnet account from the equity observations, with a hypothetical scope (USDC, HYPE and the validator DEX) given on the command line. It records what the unpinned HTTP API listed for the account and the report calls the watcher would propose for the eleven tokens, one perp DEX and one HyperCore vault outside that scope. No source or verifier is deployed, so no call was simulated and `toSend` is empty: the file shows that the listing and the call construction work on live data, not that any report would stand. Nothing was signed or sent. `managed-scope-watch-2026-10-05.json` is the same kind of run by the later version of the script, which adds `hintUsdc` to each proposed call: a rough value from unpinned API balances and mid prices, used only to choose the single report the source keeps. The hints are not valuations and must not be added up.

`managed-spot-book-empty-side-2026-10-05.json` was collected by `scripts/book_probe.py`: for seven USDC-quoted spot pairs that the HTTP API listed with an empty bid side, ask side or both, it records the `bbo` and `spotPx` precompile answers at one pinned EVM block with a final block-hash check. Every `bbo` read answered, the empty sides read as zero, and `spotPx` stayed non-zero. The HTTP book reads are unpinned, so a book may have changed between the two reads. One block and seven pairs: a sample, not a protocol guarantee. Nothing was signed or sent. [Interpretation](../managed-precompile-evidence.ko.md#empty-book).

`managed-asset-preflight-initial-2026-10-11.json` and `managed-asset-preflight-2026-10-11.json` are read-only, block-pinned token metadata/decimals/reserve checks from `scripts/managed_asset_preflight.py`. The initial capture incorrectly applied the ERC20 extra-decimals identity to native HYPE and retains that failure. The second capture handles native HYPE separately (EVM 18, Core 8), verifies USDC 6/8 and UBTC 8/10, and rechecks the block hash. These observations do not test transfer execution, system liquidity, account activation, minting, or a Core round trip. No wallet or signing key was used.
